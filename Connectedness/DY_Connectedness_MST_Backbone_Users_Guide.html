1 · Quick start

1
Open the tool and click Load bundled example data — or upload your own CSV (format in Section 2).
2
In panel 2, keep the defaults (VAR lag p = 1, horizon H = 10, Cholesky order “As in file”) and click Run analysis.
3
Read the results in panels 3–7: the summary KPIs and net-connectedness rankings, the full connectedness tables, the dense spillover networks, the three minimum spanning trees, and the directed consensus backbone.

The tool is a single HTML file: it runs entirely in your browser, needs no installation or internet connection, and your data never leave your machine. Every panel has a 📖 Method notes link. The guide and method pages open in the same tab, while the tool keeps the loaded data, settings, calculated results, and scroll position in session storage. Returning to the tool restores that working state automatically; closing the tab discards it.

2 · Data inputs

The tool accepts a single CSV (comma- or tab-separated) laid out as a time-series matrix: each column is one variable (a market, asset, or institution) and each row is one time period. This is the standard “wide” format produced by almost any data provider.

Layout

An optional date/label column may appear first; the tool detects it and any other non-numeric columns and ignores them automatically, computing only on the numeric series. The first rows of the bundled example (12 global markets, weekly, 2015 onward):

DateUS_EQEU_EQJP_EQ…OILGOLD
2015-01-05-0.3820.4911.360…0.1841.213
2015-01-120.5290.2710.551…-1.4850.471
2015-01-19-1.488-0.264-0.143…0.246-0.374

The example’s twelve series are four equity indices (US_EQ, EU_EQ, JP_EQ, CN_EQ), four 10-year sovereign yields (UST_10Y, BUND_10Y, JGB_10Y, CGB_10Y), two currencies (USD, EUR), and two commodities (OIL, GOLD). On load the status line confirms how many series and observations were read and lists the series names.

Pre-process before loading

The tool computes a VAR on exactly the numbers you provide. It does not transform your data. A connectedness VAR should be estimated on series that are (approximately) stationary — so convert prices or index levels to returns or log-differences, and yields to changes, before loading. The bundled example is already in standardized-return form.

You may, if you wish, standardize each series (subtract the mean, divide by the standard deviation) so that contributions are comparable across markets of very different volatility; this is optional and does not change the generalized decomposition’s order-invariance.

Validation rules

You need at least two numeric series. Numbers must use a dot as the decimal separator, with no thousands separators or currency symbols. There must be comfortably more observations than parameters: a VAR(p) on k series estimates 1 + k×p coefficients per equation, so the tool requires the number of usable rows (T − p) to exceed that — and warns if you are close to the limit. Reduce the lag length or supply more data if you hit this.

Use Download example CSV in panel 1 to save the bundled data (example_data.csv) as a template for your own file.

3 · Model settings (panel 2)

ControlWhat it does & how to choose
VAR lag length p The number of own- and cross-lags in the vector autoregression (default 1). Higher p captures richer dynamics but consumes degrees of freedom fast. For weekly/monthly macro-financial returns p = 1–2 is usually enough; pick by an information criterion if you have one in mind, and watch the “too few observations” guard.
Forecast horizon H The forecast-error-variance horizon over which spillovers are measured (default 10). Short horizons emphasize immediate transmission; longer horizons let indirect, multi-step spillovers accumulate. Connectedness typically rises with H and then stabilizes — try 5, 10, 20 to see the plateau.
Cholesky variable order Controls only the orthogonalized (Cholesky) decomposition. As in file uses the column order; Reversed flips it; Custom lets you type a comma-separated list of all series names (exactly once each). Earlier variables are treated as more “exogenous”. Change it to see how sensitive the Cholesky result is — the generalized result does not move.
Two decompositions, side by side. Decomposition 1 is the Diebold-Yilmaz (2012) generalized FEVD: it is order-invariant (for a linear VAR it coincides with the Lanne-Nyberg 2016 decomposition) and is the headline result. Decomposition 2 is the orthogonalized Cholesky FEVD, which depends on the variable order. Showing both lets a workshop audience see exactly how much the identification assumption matters.

4 · Walkthrough with the bundled example

The example is a synthetic but internally consistent panel of twelve global markets in standardized-return form. Follow along:

1
Load. Click Load bundled example data. The status line confirms 12 series and the number of weekly observations, and lists the names. The Custom-order box is pre-filled with the file order so you can edit it later if you want.
2
Run. Keep the defaults (p = 1, H = 10, order “As in file”) and click Run analysis. The results section appears and the page scrolls to it.
3
Summary (panel 3). Read the four KPI cards: the total connectedness index (TCI) for each decomposition — the share of total forecast-error variance that is cross-market — and the current largest companion-root modulus, residual degrees of freedom, top net transmitter and top net receiver. The root modulus must be below one for a stable VAR. The two net-directional bar charts rank every market: red bars are net transmitters of shocks, blue bars net receivers. Compare the generalized ranking with the Cholesky one to gauge order-sensitivity.
4
Connectedness tables (panel 4). Each cell (i, j) is the percentage of market i’s H-step forecast-error variance explained by shocks to market j; rows sum to 100. The margins give FROM (received from others), TO (transmitted to others), NET = TO − FROM, and the TCI. The two matrices below the tables report net pairwise transmission: a positive row-i/column-j cell means i dominates j within that pair.
5
Networks (panel 5). The dense directed spillover graph for each decomposition. Drag the edge-threshold slider to thin weak links and reveal the dominant channels; switch between the circular (DY/Gabauer standard) and Fruchterman-Reingold layouts.
6
Minimum spanning trees (panel 6). Three trees built from three reduction rules (Section 5). Use the Build MSTs from selector to switch between the generalized and Cholesky decompositions and try the different tree layouts.
7
Consensus backbone (panel 7). The directed sparsification. Start with the defaults (kr = 3 roots, kp = 3 arborescences per root, penalty γ = 0.5, doubly-stochastic normalization) and read the diagnostic cards, including the Suggested k*. See Section 6 for how to tune it.

Every result reacts live to the controls inside each panel — moving the threshold slider, switching layouts, or changing the backbone parameters re-renders immediately without a fresh Run analysis. Re-run only when you change the data, the lag, the horizon, or the Cholesky order.

5 · Reading the results, panel by panel

OutputHow to read it
KPI cards (panel 3) TCI = system-wide connectedness (higher = more integrated/contagious); top net transmitter and receiver are the current extremes of the NET ranking. Two TCI cards (generalized vs Cholesky) show how much the identification choice moves the headline number.
Net-directional rankings NETi = TOi − FROMi. Red (positive) = net source of shocks; blue (negative) = net absorber. Bar length is scaled to the largest absolute net value.
Connectedness table A pairwise variance-decomposition matrix. Row i = where market i’s uncertainty comes from; column j = where market j’s shocks go. Cell shading scales with the off-diagonal magnitude; the bottom rows give TO and NET, the right column FROM, and the corner the TCI. The net-pairwise matrices below show C(i→j) − C(j→i).
Dense network (panel 5) Node colour = net role (red transmitter, blue receiver); node size = total connectedness (TO + FROM); arrows point transmitter → receiver with width and opacity scaled to the pairwise directional connectedness. The threshold is expressed as a percent of the strongest edge.
Minimum spanning trees (panel 6) The connectedness network is directed, so each reciprocal pair (i→j and j→i) must be reduced to one undirected weight before a tree can be built. Three economically distinct rules are shown, each as a maximum spanning tree (it keeps the strongest links):
Criterion 1 — Sum: C(i→j) + C(j→i), total bilateral connectedness (co-movement clusters).
Criterion 2 — Absolute difference: |C(i→j) − C(j→i)|, net asymmetry (who dominates whom).
Criterion 3 — Maximum: max of the two, the dominant one-way channel (principal propagation routes).
Consensus backbone (panel 7) A directed sparsification (Chan-Lau 2026): the union of maximum directed spanning trees (arborescences) rooted at the top emitters. Arrowheads show spillover direction; edge thickness = frequency across arborescences; node size = emitter strength; a gold ring with a star marks a root. The diagnostic cards report the roots, edge count, weight retained, density, reachability, raw-weight out-strength R², and the suggested k*. The directional-measure bar chart underneath lets you rank nodes by net/out/in strength or degree.

6 · The consensus backbone in detail (panel 7)

The backbone is the tool’s most configurable panel. Unlike an MST it preserves both direction and redundancy, so alternative spillover routes survive.

ControlWhat it does & how to choose
Source decomposition Build from the generalized (DY 2012) or the Cholesky table. Generalized is the default and is order-invariant.
Normalization Doubly-stochastic (Sinkhorn) — the recommended default — exposes the scale-invariant latent structure. Row-stochastic emphasizes emission profiles; column-stochastic emphasizes receiver vulnerability. Each changes which links survive. The tool verifies positive support and numerical convergence; an infeasible Sinkhorn scaling is reported instead of used.
Roots kr How many top emitter nodes to root arborescences at. More roots = more of the network covered.
Arborescences per root kp How many edge-diversified trees each root contributes (a “branching pack”). More packs = more redundant routes retained.
Penalty γ The edge-reuse factor (0.05–0.95) applied after each use. Lower γ imposes a stronger penalty and produces more diversified routes; higher γ permits more reuse.
Layout Kamada-Kawai, Fruchterman-Reingold, or Circular — positions only, never the data.
Suggested k*. The diagnostic card applies a composite saturation criterion: after the first gain, it stops at the first kp whose marginal gain in the combined weight / density / reachability / raw out-strength-R² score falls below 10% of that first step. It is a principled starting point — set kp to the suggested k*, then adjust to taste.
Read the diagnostics together: weight retained is how much of the total spillover mass the sparse backbone keeps; density is the fraction of all possible directed edges it uses; reachability is how much of the network the backbone still connects; and raw out-strength R² compares retained and full-network transmitter strengths on the same unnormalised edge scale. A good backbone keeps most of the weight and reachability with only a small fraction of the edges.

7 · Network & tree layouts

Layouts change only the positions of the nodes, never the underlying numbers. Each emphasizes something different:

LayoutWhat it shows best
Circular (DY/Gabauer standard) All markets on one ring. Because positions are fixed and neutral the edges stand out — the cleanest view of who spills over to whom, and ideal for comparing the generalized and Cholesky graphs side by side. The default for the dense networks.
Kamada-Kawai On-screen distances approximate shortest-path distances. The best general-purpose overview: central markets end up central, peripheral ones drift outward. The default for the trees and backbone.
Fruchterman-Reingold (spring) Linked markets attract, all markets repel. In the dense panel, only threshold-surviving bilateral links act as springs and their strength scales attraction, so moving the threshold recomputes the layout.

The dense-network panel offers Circular and Fruchterman-Reingold; the MST and backbone panels add Kamada-Kawai. All force-based layouts are computed deterministically, so each picture is reproducible.

8 · Preparing your own data

A practical checklist:

1
Shape the file. One column per variable, one row per period, an optional date column first. Keep column headers short and free of commas.
2
Make it stationary. Convert price/index levels to returns or log-differences and yields to changes before loading. Estimating connectedness on non-stationary levels produces spurious spillovers.
3
Align dates and clean gaps. All series on the same calendar with no missing cells in the numeric block; drop or impute holidays consistently. The tool reads the numbers as given.
4
Mind the dimensions. Keep enough rows relative to k and p (see the validation rule in Section 2). With many series, start at p = 1.
5
Sanity-check on load. The status line should report the series count and names you expect. If a column you wanted is missing, it was non-numeric and got dropped — check for stray text or symbols.
6
Vary the horizon. Re-run at a few horizons (H = 5, 10, 20) to confirm your connectedness conclusions are not an artefact of one choice.

9 · Troubleshooting

SymptomCause & fix
“Need at least 2 numeric series.” Only one numeric column was detected. Other columns were treated as labels — check for text, symbols, or thousands separators that turned a numeric column non-numeric.
“Too few observations…” A VAR(p) on k series needs comfortably more than 1 + k×p rows per equation. Lower the lag length or supply more data.
“Custom order must list all series names exactly once.” The custom Cholesky order is missing a name, has a typo, or repeats one. Copy the names from the status line; the box is pre-filled with the file order as a template.
“estimates may be imprecise” warning The run succeeded but there are few usable rows per parameter. Treat the numbers as indicative; reduce p or add data for firmer estimates.
“The fitted VAR is unstable…” The estimated largest companion-root modulus is at least one, so the stationary Wold/FEVD interpretation does not apply. Use returns or differences, reduce the lag length, or revise the model.
“Sinkhorn normalization did not converge…” The selected decomposition and horizon do not provide support for a doubly-stochastic scaling. This can occur for a short-horizon Cholesky FEVD. Choose row/column normalization, a longer horizon, or generalized FEVD.
Cholesky result changes a lot with order; generalized does not Expected — that is the point of showing both. The order-dependence is a property of orthogonalized decompositions; rely on the generalized result for order-free conclusions.
A column you expected is absent from the results It was non-numeric and auto-ignored. Remove text/symbols, or move a genuine label into the first (date) column.
